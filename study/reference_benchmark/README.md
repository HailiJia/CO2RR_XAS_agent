# Numeric Cu reference benchmark

Run `python study/reference_benchmark/process.py` from any directory (Python, NumPy, pandas, SciPy, matplotlib). Execute the revised notebook using Jupyter or `python study/reference_benchmark/execute_notebook.py` with nbformat and IPython. The latter runs every code cell through IPython without opening kernel sockets.

The original notebook is unchanged at `raw/Cu_XAS.ipynb`. `original_notebook_cells.json` audits every cell. The notebook uses sigma=1 eV, inconsistent +120/+124/+125/-8/-9 eV shifts, and an intensity array reused across methods. Its zero-byte PBE export cannot execute cleanly. The orphan Cu_GW.dat lacks verified lineage to the OUTCARs; it is preserved, not silently substituted.

`source_inventory.json` inventories all 503 supplied files (about 55.6 GB), including exclusions. An explicit allowlist copies only relevant spectra, input settings, structures and logs (165 files, about 10 MB). Native large text logs are losslessly gzip-compressed with deterministic headers; both original and stored SHA-256 are recorded. Wavefunctions, charge exports, licensed potentials, executable binaries, hidden/checkpoint files and unrelated intermediates remain excluded. No LFS mechanism exists in this repository; each included file is below GitHub's ordinary file limit. This is a curated reference upload, not a full simulation export.

The 18-row `provenance.csv` records material/formal oxidation state, source, columns/units, energy convention, averaging, prior processing, calculation settings, limitations and SHA-256. Formal Cu(0/I/II) labels are distinct from atomic charges. `missing_series_matrix.csv` preserves all three missing computational slots: Cu2O PBE, Cu2O “GW”, and CuO PBE. All three experimental columns are present. Empty/missing output is never filled from another method or compound. Metallic PBE is extracted from its actual OUTCAR, not the empty export.

Oxide FDMNES folder names are reversed relative to the decks/logs. Modes are classified from Green/input and finite-difference/output evidence, with original paths retained. The VASP “GW” folder is an alias: its recorded inputs/output show a supercell core-hole treatment without a verified GW/BSE step. The nominal metallic experimental header describes a 100 nm Cu electrode at -0.4 V, not a certified bulk foil. Experimental polarization, upstream processing, instrument resolution and independent calibration metadata are not provided.

`settings.json` specifies every width, shift sign, operation, window, fitting bound/objective/degree of freedom, interpolation rule, software environment, and source fingerprint. Completed FDMNES energy-dependent convolutions and FEFF intrinsic lifetime treatment are retained without a second lifetime convolution. VASP and unconvolved CuO FDM receive an explicit comparison estimate of constant Lorentzian FWHM=1.55 eV, HWHM=0.775 eV, using the logged Cu K parameter as a prescription, not as a verified version-specific width convention. The latter lacks the missing final-state loss prescription, so CuO FDM cannot isolate solver accuracy. The primary added Gaussian sigma/FWHM is zero because measured instrument resolution is absent. A separate unvalidated sensitivity uses the notebook's sigma=1 eV, FWHM=2.35482 eV; widths are never fitted. VASP's existing CH_SIGMA is preserved; its executable-specific sigma/FWHM convention is not independently established.

The short FDMNES range cannot support conventional long-range pre-edge regression. Constant local pre-edge subtraction and local edge-jump scaling use the explicit fixed source intervals in `normalization.csv`; no missing background is extrapolated. Calculated source windows are chosen once, before fitted shifts. The nominal offsets used to choose those intervals differ from the fitted calibration offsets. These conditional short-window comparisons are not standardized absolute-accuracy measurements. Archived ML preprocessing remains minimum-subtracted/unit-area and is unchanged.

`metrics.csv` and exact `plotted_arrays.csv` separate:

- Native zero-shift axes, with supported intersections only (VASP can have insufficient or tail-only overlap).
- One Cu-fitted offset per backend, shared across compounds and both FDMNES modes; no independent oxide calibration in this view.
- Optional per-compound/method shape alignment, one residual shift bounded to ±20 eV; chemical shifts are removed.
- The added-Gaussian sensitivity at the common offsets.

RMSE is in experimental local edge-jump units; common comparisons use 8980–9020 eV and 201 linearly sampled points, without extrapolation. Correlation and global-peak differences are reported only when meaningful; robust edge differences are unavailable. Raw, lifetime-treated and normalized arrays are saved in `processed/`. PDF/SVG/450-dpi PNG grids have three compounds by five calculations, black experiment and consistent method colors. Missing cells stay blank.

Common-offset Green RMSE is 0.0539/0.1031/0.1378 for Cu/Cu2O/CuO. Corresponding FDM values are 0.0896/0.1069/0.9540; the last has incomplete final-state processing. FEFF gives 0.1002/0.2489/0.2118. Cu2O FDM slightly beats Green after separate shape alignment (0.1019 vs 0.1023) and the extra-Gaussian sensitivity (0.1003 vs 0.1021). These are processing-conditional findings, not a universal ranking or operating-interface transfer validation. VASP residuals and correlations are disclosed even when poor. `runtime_inventory.json` discloses CPU counters and different resource requests; hardware/accounting are incomplete, so no measured speedup is claimed.

Primary documentation: [VASP CH_SIGMA](https://vasp.at/wiki/index.php?title=CH_SIGMA&oldid=28409), [VASP core-hole calculations](https://vasp.at/wiki/Supercell_core-hole_calculations), [FEFF 9.6.4 guide](https://feff.phys.washington.edu/FEFF/Docs/feff9/feff90/feff90_users_guide.pdf), [FDMNES guide](https://data-analysis.synchrotron-soleil.fr/tmp/software/fdmnes/fdmnes_Linux/Doc/Manual_Eng.pdf). The available FDMNES guide cover is November 2022. Neither its correspondence to the 2025 reference executable nor the separate July 2026 ML executable has been established. Current core-hole metadata remains not_reported; ML convolution logs remain 332 present and 16 absent.
